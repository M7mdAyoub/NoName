# مراجعة تجربة الاستخدام — قياس / ImpactOS

تحديث المتطلبات: 24 أكتوبر 2026. المطلوب: واجهة عربية أولاً، خلفيات كريمية وبيضاء، تباين قوي، خط واضح وكبير، مسار عمل أبسط، وإزالة البيانات الوهمية.

## نتائج التدقيق والإجراءات

| الأولوية | المشكلة في النسخة السابقة | الإجراء |
|---|---|---|
| عالية | نصوص وعناوين ثانوية بحجم 6–11 بكسل؛ يصعب قراءتها | اعتماد IBM Plex Sans Arabic، نص أساسي 16 بكسل، عناصر الجداول والحقول 14–16 بكسل، وعناوين 24–34 بكسل |
| عالية | ألوان باهتة وشفافية مفرطة للنصوص والحدود | نص داكن صريح على الأبيض والكريمي؛ قياس نسب التباين؛ عدم الاعتماد على اللون وحده للحالات |
| عالية | واجهة إنجليزية وتخطيط من اليسار | العربية لغة المستند واتجاه RTL حقيقي؛ أكواد وروابط وأرقام معزولة باتجاه مناسب |
| عالية | أرقام واستجابات وأسماء وأقوال مصطنعة توحي ببيانات تشغيلية | حذف بيانات العرض من التطبيق وإصدار تخزين جديد يتجاهل بيانات النسخة القديمة؛ الحالات الفارغة تشرح المطلوب |
| عالية | مسارات كثيرة لا تتوافق مع أحدث نطاق المستودع | اعتماد مسار MVP: رفع الإطار، مراجعة ونشر، جمع البيانات، النتائج؛ الوثائق والمصادر منفصلة عن خطوات العمل |
| عالية | مؤقتات توهم بوجود استخراج وتحليل فعلي | لا محاكاة ولا توليد خلفي. عمليات التحليل والإرسال والنشر تستخدم واجهات API الفعلية فقط عند الاتصال |
| متوسطة | ازدواجية التفاصيل والعبارات التسويقية في لوحة العمل | عنوان ووصف قصير وإجراء أساسي واحد في كل شاشة، والتفاصيل المطولة داخل أقسام قابلة للفتح |
| متوسطة | عناصر صغيرة لا تناسب اللمس | ارتفاع تفاعلي لا يقل عن 44 بكسل ومسافات واضحة بين الإجراءات |
| متوسطة | تدفق النشر غير مطابق للخادم الحالي | ربط المراجعة بنقاط PATCH وPUT وPOST الموثقة في الشيفرة الحالية، وإظهار أخطاء الخادم في سياقها |
| متوسطة | تمرير أفقي غير مقصود وحقول مخفية تسبب أخطاء | حصر تمرير الجداول داخل حاوياتها، وتحقق حقول موضعي، وحفظ قيمة الصفر بدلاً من معاملتها كقيمة مفقودة |
| متوسطة | اختلاف مصدر المعلومات وعدم وضوح حالتها | إظهار روابط GitHub الأصلية، ونسخة الشيفرة المرجعية، والتمييز بين وثائق النظام وبيانات المشروع الفعلية |

## المصدر الفعلي

المستودع الأصلي NoName أصبح [M7mdAyoub/Qiyas](https://github.com/M7mdAyoub/Qiyas). أحدث نطاق قرئ هو [docs/MVP.md](https://github.com/M7mdAyoub/Qiyas/blob/b342a953a165fe1c8ba504c6cc3ff345c61c035a/docs/MVP.md)، مع مراجعة نقاط API في الشيفرة عند المرجع نفسه.

المستودع يتضمن شيفرة ووثائق وملفات اختبار مصطنعة؛ هذه الملفات ليست سجلات تشغيل حقيقية. لا تستخدمها الواجهة كمشروعات أو استجابات أو نتائج. تعرض مكتبة المصادر وثائق البرامج العامة التي يسردها docs/plan/public_result_framework.md، مع روابطها الأصلية، دون الادعاء باستيراد مؤشرات أو نتائج منها.

يبقى طلب المستخدم بالعربية وRTL سارياً حتى لو استبعد نطاق MVP القديم تعدد اللغات. لا تغييرات على الخادم أو المستودع البعيد ضمن هذا العمل.

## معايير التحقق

- اختبار أحجام مكتبية وهاتفية، RTL، المسار الكامل، التركيز ولوحة المفاتيح، النصوص الطويلة، حالات التحميل والخطأ والفراغ.
- قياس تباين النصوص الأساسية والثانوية والأزرار؛ الهدف AA: 4.5:1 على الأقل للنص العادي.
- لا تستبدل أخطاء الاتصال ببيانات مصطنعة؛ لا ترسل ملفات قبل اختيار الخادم والضغط على الرفع.
- بناء إنتاجي ناجح واختبارات لحماية البيانات الفارغة، طلبات API، التحقق من الملفات والحقول، وعدم عرض null على أنه صفر.
- تسجل نتائج التحقق الفعلية في نهاية الملف عند اكتمال العمل.
